# Kerio Control UTM → Wazuh SIEM

[English](README.md) | **Русский**

Передача критических событий безопасности из **Kerio Control UTM** (модуль предотвращения вторжений IPS, антивирус, блокировки сетевых атак, Anti-hammering / защита от подбора паролей) в **Wazuh SIEM**: приём по Syslog (UDP 514), нормализация событий, правила и корреляция. События уровня 10 и выше транслируются в Telegram-чат оперативного оповещения.

Совместимость: Kerio Control 9.x, Wazuh 4.x.

## 1. Требования

- Сервер **Wazuh manager** 4.x (Linux с systemd, `bash`, `python3`, `iproute2`, права `root`).
- Шлюз **Kerio Control UTM** 9.x с доступом к веб-консоли администратора.
- Сетевой доступ от шлюза Kerio Control к менеджеру Wazuh по протоколу **UDP**, порт **514**.

---

## 2. Установка на менеджере Wazuh

Выполните на сервере Wazuh:

```bash
cd kerio-control-integration-with-wazuh-siem
cp config.env.example config.env
sudo chown root:root config.env && sudo chmod 600 config.env
sudo nano config.env
```

В `config.env` укажите:
- `KERIO_IP`: IP-адрес интерфейса Kerio Control или CIDR-подсеть, с которой отправляется Syslog (например, `192.0.2.1` или `192.0.2.0/24`).
- `LISTEN_IP`: IP-адрес интерфейса Wazuh Manager для прослушивания (например, `192.0.2.10` или `0.0.0.0`).

Проверка и установка:

```bash
# 1. Посмотреть точный diff планируемых изменений (без модификации файлов):
sudo ./deploy.sh plan

# 2. Применить конфигурацию (автоматический бэкап, проверка logtest, перезапуск службы):
sudo ./deploy.sh install
```

Скрипт добавит в `/var/ossec/etc/ossec.conf` изолированный блок `<remote>` для UDP 514, скопирует декодер и правила, проверит корректность синтаксиса и перезапустит `wazuh-manager`. В случае ошибки скрипт автоматически вернёт предыдущую рабочую конфигурацию из бэкапа.

## 3. Настройка Kerio Control UTM

Настройка производится в веб-интерфейсе администратора Kerio Control:

1. Перейдите в левой панели в раздел **Журналы** (иконка документа с загнутым уголком).
2. Выберите журнал **Security**.
3. Кликните правой кнопкой мыши по списку событий и выберите **«Настройка протокола…»**.
4. Перейдите на вкладку **«Внешнее протоколирование»** (External Logging):
   - Отметьте чекбокс: **«Включить протоколирование Syslog»**;
   - **Сервер Syslog**: укажите `LISTEN_IP` вашего Wazuh Manager (например, `192.0.2.10`);
   - **Обеспечение**: оставьте значение по умолчанию (`16: Local use 0`);
   - **Приложение**: укажите `KerioControl` (строго латиницей, без пробелов);
5. Нажмите **ОК**.

> [!TIP]
> При необходимости отправки дропов пакетного фильтра Firewall повторите эту операцию для журнала **Filter**.

## 4. Проверка работы

Для автоматической проверки состояния интеграции запустите:

```bash
sudo ./deploy.sh verify
```

Сквозной просмотр поступающих алертов в реальном времени:

```bash
sudo tail -F /var/ossec/logs/alerts/alerts.json | grep --line-buffered '"kerio"' \
  | jq -c '{rule: .rule.id, level: .rule.level, desc: .rule.description, src: .data.srcip, threat: .data.kerio.threat}'
```

## 5. Команды deploy.sh

| Команда | Действие |
|---|---|
| `sudo ./deploy.sh plan` | Показать планируемый diff без изменения системы |
| `sudo ./deploy.sh install` | Установить / обновить интеграцию с бэкапом и валидацией |
| `sudo ./deploy.sh test` | Прогнать набор тестовых событий через `wazuh-logtest` |
| `sudo ./deploy.sh verify` | Проверить статус службы, сокетов, правил и логов |
| `sudo ./deploy.sh rollback` | Полный откат интеграции и удаление правил |

## 6. Правила и уровни критичности

Выделенный диапазон ID: `100800`–`100899`.

По умолчанию в Wazuh во внешние интеграции (включая Telegram) транслируются оповещения с уровнем важности **10 и выше**. Фоновые и высокочастотные события (дропы по репутационным базам Spamhaus, сканирования портов, проверки версий ПО) классифицируются уровнем **6** — они полноценно индексируются в SIEM для расследований (Threat Hunting), но не перегружают Telegram шумом.

| Rule ID | Уровень | Описание | Оповещение в Telegram |
|---|---|---|---|
| **100800** | 0 | Базовое событие Kerio Control | Нет |
| **100809** | 5 | Базовый диспетчер событий IPS | Нет |
| **100801** | 6 | Сигнатура IPS Alert (уровень Medium/Low: аудит, версии ПО, поиск IP через SNI) | Нет |
| **100807** | 10 | Сигнатура IPS Alert [High] (критичные попытки атак и нарушения политик) | **Да** |
| **100802** | 10 | Срабатывание IPS Packet Drop (эксплойт, прямая сетевая атака) | **Да** |
| **100803** | 6 | Блокировка трафика из черных списков репутации (Spamhaus DROP, Botnet C2, Dshield) | Нет |
| **100805** | 6 | Обнаружение сетевого сканирования портов (Port Scan) | Нет |
| **100806** | 11 | Вредоносный объект заблокирован антивирусом Kerio | **Да** |
| **100804** | 12 | IP заблокирован за перебор паролей (Anti-hammering) | **Да** |
| **100810** | 13 | Корреляция: серия повторных атак/дропов с одного IP за 2 минуты (от 3 событий) | **Да (Критический)** |

## 7. Обновление и откат

Все резервные копии сохраняются в `/root/kerio-control-integration-with-wazuh-siem-backups/`. 

Для полного отката выполните:
```bash
sudo ./deploy.sh rollback
```
Или восстановите конкретную резервную копию:
```bash
sudo ./deploy.sh rollback --from-backup /root/kerio-control-integration-with-wazuh-siem-backups/<TIMESTAMP>
```
